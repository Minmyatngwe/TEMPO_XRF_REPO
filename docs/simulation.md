# Running a Simulation

`RoboAiXrfSimulation` controls the main XRF simulation workflow.

It is responsible for:

* preparing the X-ray source spectrum
* writing the Geant4 configuration
* running Geant4
* storing the simulation result
* stopping a running simulation
* processing the simulated detector response

Import it with:

```python
from roboaixrf import RoboAiXrfSimulation
```

---

# Creating a simulation

A simulation requires:

* an `XRFConfigure` object
* a directory where the run files will be stored

Example:

```python
from pathlib import Path

from roboaixrf import RoboAiXrfSimulation

simulation = RoboAiXrfSimulation(
    config=config,
    config_path=Path("runs/iron_sample"),
)
```

The configuration must already contain:

* sample
* detector
* X-ray tube
* physics configuration

The directory:

```text
runs/iron_sample
```

is used to store files generated by the simulation.

---

# Simulation workflow

The normal workflow is:

```python
simulation = RoboAiXrfSimulation(
    config=config,
    config_path=Path("runs/iron_sample"),
)

simulation.compile()

simulation.run(
    beam_on=100_000,
    number_of_thread=4,
)
```

The important order is:

```text
create configuration
        ↓
create simulation
        ↓
compile()
        ↓
run()
```

`compile()` must be called before `run()`.

---

# `compile()`

Use:

```python
simulation.compile()
```

to prepare the simulation.

Example:

```python
from pathlib import Path
from roboaixrf import RoboAiXrfSimulation

simulation = RoboAiXrfSimulation(
    config=config,
    config_path=Path("runs/test_run"),
)

simulation.compile()
```

`compile()` prepares the source spectrum and writes the Geant4 configuration.

After compilation, you can check:

```python
print(simulation.is_compiled)
```

which should return:

```text
True
```

---

# What `compile()` creates

The configuration is written to:

```text
config.json
```

inside the simulation directory.

For example:

```text
runs/
└── iron_sample/
    └── config.json
```

The X-ray tube source spectrum is also generated and stored internally for the Geant4 run.

---

# Source spectrum

After `compile()`, the source energy bins can be accessed with:

```python
simulation.energy_bin
```

and the corresponding relative fluence values with:

```python
simulation.fluence_list
```

For example:

```python
print(simulation.energy_bin)
print(simulation.fluence_list)
```

These arrays define the photon-energy distribution used by the Geant4 General Particle Source.

---

# `run()`

Use `run()` for a normal blocking Geant4 simulation.

Example:

```python
simulation.run(
    beam_on=100_000,
    number_of_thread=4,
)
```

The function waits until the Geant4 simulation has finished.

---

# `beam_on`

`beam_on` defines the number of primary Geant4 events.

For example:

```python
beam_on=100_000
```

means that Geant4 simulates:

```text
100,000 primary events
```

A larger number normally improves the statistical precision of the simulated spectrum but also increases computation time.

For example:

```python
simulation.run(
    beam_on=1_000_000,
    number_of_thread=8,
)
```

runs one million primary events.

---

# `number_of_thread`

`number_of_thread` controls the number of Geant4 worker threads.

For example:

```python
number_of_thread=4
```

uses four worker threads.

A complete call is:

```python
simulation.run(
    beam_on=500_000,
    number_of_thread=4,
)
```

Both values must be greater than zero.

---

# Simulation output

A successful quantitative Geant4 run produces:

```text
simulation.root
```

inside the run directory.

For example:

```text
runs/
└── iron_sample/
    ├── config.json
    ├── run.mac
    └── simulation.root
```

`simulation.root` contains the detector events produced by the Geant4 simulation.

This file is later used when detector response and detector noise are applied.

---

# Number of simulated events

After a successful run, the number of registered primary events can be accessed with:

```python
simulation.beam_on
```

Example:

```python
simulation.run(
    beam_on=100_000,
    number_of_thread=4,
)

print(simulation.beam_on)
```

After a successful run:

```text
100000
```

is stored.

---

# Starting a simulation in the background

For applications that must continue running while Geant4 is executing, use:

```python
simulation.start_run(...)
```

instead of:

```python
simulation.run(...)
```

Example:

```python
process = simulation.start_run(
    beam_on=1_000_000,
    number_of_thread=8,
)
```

`start_run()` returns the Geant4 process immediately.

This is useful for graphical interfaces or applications that need to provide controls while the simulation is running.

For example, the process state can be checked with:

```python
if process.poll() is None:
    print("Simulation is still running.")
else:
    print("Simulation has finished.")
```

---

# `run()` vs `start_run()`

Use:

```python
simulation.run(...)
```

when your Python program should wait for Geant4 to finish.

Use:

```python
simulation.start_run(...)
```

when your application needs access to the running process.

Conceptually:

```text
run()
│
├── starts Geant4
└── waits until it finishes
```

while:

```text
start_run()
│
├── starts Geant4
└── immediately returns the process
```

---

# Stopping a running simulation

A simulation started with `start_run()` can be stopped with:

```python
simulation.stop_run(process)
```

Example:

```python
process = simulation.start_run(
    beam_on=10_000_000,
    number_of_thread=8,
)

# Stop the simulation if required
simulation.stop_run(process)
```

When a run is stopped, a partial `simulation.root` file is removed because it should not be used as a valid quantitative detector response.

---

# Complete basic example

Assume that `config` is an already completed `XRFConfigure` object.

```python
from pathlib import Path

from roboaixrf import RoboAiXrfSimulation

# Create the simulation controller
simulation = RoboAiXrfSimulation(
    config=config,
    config_path=Path("runs/iron_sample"),
)

# Prepare the source spectrum and configuration
simulation.compile()

# Check compilation
print(
    "Compiled:",
    simulation.is_compiled,
)

# Run Geant4
simulation.run(
    beam_on=100_000,
    number_of_thread=4,
)

# Check how many primary events were simulated
print(
    "Beam on:",
    simulation.beam_on,
)
```

After the run, the directory should contain files similar to:

```text
runs/
└── iron_sample/
    ├── config.json
    ├── run.mac
    └── simulation.root
```

---

# Required order

The correct order is:

```python
simulation = RoboAiXrfSimulation(
    config=config,
    config_path=Path("runs/test"),
)

simulation.compile()

simulation.run(
    beam_on=100_000,
    number_of_thread=4,
)
```

Do not call:

```python
simulation.run(...)
```

before:

```python
simulation.compile()
```

because the X-ray source spectrum and Geant4 configuration have not yet been prepared.

---

# After the Geant4 run

The raw Geant4 response does not yet represent the final measured detector spectrum.

The next stage is:

```python
simulation.detector_noise(...)
```

which scales the simulated detector response to a physical acquisition and applies detector effects such as:

* energy resolution
* Fano statistics
* electronic broadening
* pile-up
* MCA channel calibration

Detector response processing is documented separately.
